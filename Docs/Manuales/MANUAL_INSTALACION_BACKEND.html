Arquitectura y Secretos

Generación de firmas RS256 para JWT y clave del microcontrolador

El backend de SwiftyRing funciona como servidor de identidad y reloj central. Antes de encender los contenedores Docker, es obligatorio preparar el par de claves RSA:

cd backend/SwiftyRing
mkdir -p keys

# 1. Generar el par de llaves asimétricas RS256 para JWT (RF-44)
openssl genrsa -out keys/jwt_private.pem 2048
openssl rsa -in keys/jwt_private.pem -pubout -out keys/jwt_public.pem
chmod 600 keys/jwt_private.pem

# 2. Generar llave criptográfica compartida para el ESP32 (cabecera X-Device-Key)
openssl rand -hex 24
Permisos de Usuario Docker (Vapor UID 999) La imagen Docker corre como el usuario vapor (UID 999). Para que pueda leer la clave privada montada como solo lectura, ejecute:
echo "SWIFTYRING_GID=$(id -g)" >> .env.production y asigne chmod 640 keys/jwt_private.pem.

Despliegue y Puesta en Producción

Compilación multi-stage, migraciones relacionales y proxy inverso seguro

Comandos de Despliegue Paso a Paso

# 1. Compilar imagen de producción en Swift optimizado
docker compose -f docker-compose.prod.yml build

# 2. Levantar el contenedor de base de datos con healthcheck
docker compose -f docker-compose.prod.yml up -d db

# 3. Aplicar migraciones del esquema relacional (crea tablas y superadmin)
docker compose -f docker-compose.prod.yml --profile tools run --rm migrate

# 4. Levantar la API en segundo plano y revisar logs
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml logs -f app

Configuración de Proxy Inverso Nginx (`swiftyring.conf`)

server {
    listen 80;
    server_name swiftyring.santasofia.edu.co;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name swiftyring.santasofia.edu.co;

    ssl_certificate /etc/letsencrypt/live/swiftyring.santasofia.edu.co/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/swiftyring.santasofia.edu.co/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8020;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
